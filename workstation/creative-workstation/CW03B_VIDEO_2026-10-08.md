# CW-03B: bounded still-image video export

Implemented under the development exception; baseline and full phase qualification
remain open. This adapter exports an owned PNG as a still H.264/MP4 video. It does
not animate source JSON or establish that the PNG came from a current Electron
render. CW-03A capture reliability remains NOT QUALIFIED.

The adapter reuses canonical TaskRun admission, ScopedPolicyEngine, command
approval, ProcessRegistry, ArtifactStore and ExecutionJournal. It never creates
an alternate lifecycle store. It polls live run authority while waiting and kills
its owned child on authority loss, timeout or interruption. After output mutation,
failure produces EFFECT_UNCERTAIN with operation ID; it never retries implicitly.

Limits: 1–30 seconds, supported frame rates 15/24/25/30/60, at most 1800 frames,
even PNG dimensions within the existing 4096/8M-pixel bound, 64 MiB output, fixed
threads, 64 MiB individual FFmpeg allocation bound, 120-second encoding timeout.
These are workload bounds, not an OS-enforced total RAM quota. Fixed arguments
allow only file/pipe protocols and one video stream without audio/subtitles/data.

CLI: `python -m workstation.creative --task-id TASK --run-id RUN video`
requires project/revision IDs, absolute source PNG, its SHA-256, width and height;
duration defaults to eight seconds at 30 fps. Active config must explicitly enable
Creative and provide `creative.engines.ffmpeg` / `ffprobe` manifests. Each contains
schema_version=1, engine, absolute native executable, executable_sha256 and a
non-secret provider_ref. No engine is downloaded, installed or discovered implicitly
by this command. Binary fingerprints are rechecked before every process invocation.

Real installed-engine trial: FFmpeg/ffprobe 8.1.1 full Gyan build, audited from the
installed Chocolatey package and fingerprinted at the actual executables rather
than launcher shims. Version/configuration and `-L` output are in the receipt.
The selected build reports GPLv3 and libx264 without enable-nonfree. Executables
remain external; this change does not bundle them or approve future redistribution.

Evidence: [MP4](evidence/cw03b-20261008-trial1/video.mp4),
[decoded preview](evidence/cw03b-20261008-trial1/preview.png),
[receipt](evidence/cw03b-20261008-trial1/receipt.json).
The ephemeral real TaskRun encoded a historical PNG fixture into 360×640 H.264,
yuv420p, eight seconds, 240 decoded frames at 30 fps, 15,242 bytes.
ffprobe counted frames and independently checked container/stream timing, codec,
dimensions and file size. The decoded preview mean RGB error was 2.0294/255;
visual inspection preserved the invitation text/palette/layout. Receipt artifact
URIs describe the temporary profile used during the experiment; that profile was
removed afterward. The copied files above are the durable experiment evidence.

The first version probe failed because ProcessRegistry.wait returns a tail snapshot;
the adapter now reads the bounded complete owner log, refusing truncated/oversized
readback. A real subprocess regression preserves the header beyond a 5000-character
tail. Another real subprocess test changes canonical task authority while running
and proves child termination. These use Python test helpers and do not qualify a
media build. Four video contracts pass, plus four project/process regressions from
the focused runner. No exact-head CI or whole-product qualification is claimed.

The public CLI entrypoint also passed with real profile configuration and installed
engines: [CLI receipt](evidence/cw03b-20261008-cli/receipt.json) and
[CLI MP4](evidence/cw03b-20261008-cli/video.mp4). This calls the actual argparse/main
entrypoint inside inherited session context, rather than claiming a standalone
shell can mint that identity.

Remaining: output fault injection, packaged/runtime recovery,
native capture stabilization, and the later CW-03C/CW-04–CW-07 phases.
